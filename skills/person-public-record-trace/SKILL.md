# 机构人物公开履历溯源

## 铁律（先读这一节，它比方法更重要）

1. **绝不做"制度性倒推"当结论。** 典型错误：看到"教授级高级工程师"就说"正高职称通常要求硕士及以上"。这类推断看着专业，实际是幻觉——现行《工程技术人才职称评价基本标准条件》（人社部发〔2019〕16 号）明确正高只需**大学本科及以上**，且专设破格条款。**凡引用政策门槛，先取原文再下结论。**
2. **"查不到"≠"不存在"。** 要明确告诉用户是"公开渠道零记录"，不是"这人没学历/没毕业"。
3. **区分"实际观感"与"条文/事实"。** "这个岗位的人普遍学历高"是竞争结果，"规定要求硕士"是条文，两码事。
4. **发现自己的结论错了，立刻当面纠正并写进记忆**，不要悄悄改口。
5. **同名干扰必须单独列一节。** 中文姓名撞车极其严重（"秦玉芳"能撞到 6 个人），不列就是给用户埋雷。
6. **用途提醒写进结尾**：如果用户在背调/入职核实，公开检索只能定性、不能定论，正式结论要走对方提供的学历证明或官方渠道。

## 第一步：锁定唯一身份（最重要的一步）

搜 `"姓名" + 机构名`。不要搜"姓名 学历"！搜学历会直接落到同名的学者身上（因为**学者的学历是公开的，机构技术岗/行政岗的学历不是**）。

拿到一条能锚定单位的公开记录后（新闻稿、标准起草人名单、论文署名、奖项名单、活动通稿），记下**单位全称 + 内部部门名**，后面所有检索都带上这个锚。

## 第二步：按"信息载体"选路径（决定成败）

人物的公开度取决于 TA 走的是哪条路线：

| 路线 | 典型公开痕迹 | 学历/去向是否可得 |
|---|---|---|
| **学术路线**（研究生、高校教师） | 个人主页（`*.github.io` 很常见）、论文 affiliation、推免/录取名单 PDF、学位论文 | ✅ 通常可得，且个人主页信息最全 |
| **机构技术岗**（部委/央媒/研究院工程师） | 团体标准起草人名单、行业奖项名单、专业期刊论文、内部讲座通稿 | ⚠️ 一律只署**职务**，不署学历 |
| **行政/管理岗** | 政府任职公示、单位官网领导介绍 | 任职公示常附**学历+毕业院校**，是高价值来源 |
| **学生 / 应届毕业生** | 竞赛获奖名单、推免拟录取名单、学院新闻稿；**中心年报「毕业生概况」、实验室答辩新闻、「部分校友」页** | ✅ 在校身份好查；**就业去向也可查 —— 走机构年报/毕业生名单，见技巧三** |

## 第三步：定向检索清单（照单打，别乱搜）

按顺序试，每步记录"命中/未命中"：

1. `"姓名" + 机构名` —— 锚定身份
2. `"姓名" + 机构名 + 硕士/博士/毕业于/学位` —— 最优先
3. **行业标准/国标起草人名单** —— 团体标准、国家标准、行业规范的起草人列表，能确认部门与工作内容
4. **奖项名单** —— 行业内奖项（如新闻行业的"王选新闻科学技术奖"）获奖名单常带**完成单位 + 完整姓名列表**
5. **知网/万方作者页、会议论文集** —— 能拿到作者单位，但**拿不到作者简介**（见下节）
6. **全国专业标准化技术委员会（TC）委员名单** —— `std.samr.gov.cn` 上有「委员姓名 / 委员会职务 / 专业特长 / 加入时间」；注意该页可能已下架
7. **单位人才计划 / 先进表彰名单** —— 偶尔附个人小传
8. **同名干扰排查**：`"姓名" + 学位论文` / `"姓名" + 教授/副教授` —— 主动把撞车的人找出来并排除
9. **机构/院系的「年度报告」与「毕业生名单/部分校友」页** —— 查**就业去向**时的第一顺位，见技巧三
10. **换引擎复核**：`bing.com/search?q="姓名"` —— 默认搜索无结果时的必要动作，不是可选动作
11. **领英（LinkedIn）**、**专利库** —— 补充来源；专利的申请人单位可反查本科学校

## ★ 高价值技巧：期刊「作者简介」是纸质版专属

**这是本 skill 最值钱的一条。**

很多行业期刊强制要求文末附作者简介，且**格式固定包含学历与职称**。例如《中国传媒科技》投稿规则：

> 作者简介：姓名(出生年份—)，性别，籍贯，**学历/职称/职务**，研究方向

也就是说：**纸质版/原版 PDF 上印着这个人的出生年、学历、职称。**

但是——**知网、万方、维普、国家哲学社会科学文献中心（ncpssd）全部只收录摘要和作者单位，不收录作者简介。** 网上流传的 ChinaXiv / archive.org 版本多半是**预印本**，简介被裁掉。

**所以：**
- 不要因为数据库里没有就判定"查不到"，要说明"信息存在但只在纸质版上"
- 给用户的下一步是：**纸本期刊、图书馆原文传递、或购买当期**
- 定位方法：先在 ncpssd（`ncpssd.org`）按刊名+年+期翻目录，拿到**页码**；再去 `d.wanfangdata.com.cn/periodical/<刊号><年份><期><序号>` 试详情页（常需安全验证）
- 其他期刊同理，先查该刊的**投稿指南**确认是否强制作者简介

## ★ 高价值技巧二：机关事业单位「招聘/公示」名单

部委和事业单位的公开招聘会公开多轮名单，**不同类别的字段完全不同**，选错了就等于白看：

| 名单类别 | 典型字段 | 是否含学历/院校 |
|---|---|---|
| **拟聘用人员公示** | 招聘单位及岗位 / 姓名 / **学历学位及专业** / **毕业院校（原工作单位）** | ✅ **含，一步到位** |
| 报名、资格审查、笔试、面试、体检名单 | 序号 / 姓名 / 身份证号 / 准考证号 / 成绩 | ❌ 只含身份证号，不含院校 |
| 政府干部任职公示 | 姓名 / 性别 / 民族 / 出生年月 / **学历 / 毕业院校** / 简历 | ✅ 含（行政岗首选） |

- 拟聘公示样式由人社部事业司统一规定，见「中央和国家机关事业单位公开招聘服务平台 → 相关下载 → 拟聘人员公示（样式）」。**只要拿到这一类公示，学历+院校+原工作单位三样同时到手。**
- **身份证号前六位 = 户籍所在县区的行政区划代码**，可到民政部 `xzqh.mca.gov.cn` 或民政部《县以上行政区划代码》页查县名。**这是比"籍贯自报"更硬的佐证**（例：410821 = 河南焦作修武县）。
  - 但要注意三条边界：①它是**户籍登记地**，不等于出生地、更不等于籍贯；②它**不指向任何学校**；③"同为河南焦作人"只能证明籍贯吻合，**不能替代毕业院校字段**。
- **老公示的坑**：2012 年前后的公示页面在部委网站改版后路径常失效，站内检索也搜不到，只能用搜索引擎的全文索引碰，或**直接向用户索取原始链接**。

## ★★★ 高价值技巧三：机构年报与毕业生名单（查「就业去向」的第一入口）

**查"就业去向"时，最优来源不是新闻稿，而是机构自己出的年度报告和毕业生名单——它们会逐个列出「姓名 + 去向单位」。**

按价值排序，四个入口：

| 优先级 | 入口 | 形态 | 说明 |
|---|---|---|---|
| **1** | **中心/实验室「年度报告」（Annual Report）** | 官网「最新成果 → 年报」下的 PDF | 「人才培养 → 毕业生概况」章节逐个列 `姓名 / 去向单位`，含读博、选调、企业。**一份年报即可定案** |
| **2** | **实验室「毕业生答辩」新闻** | 实验室站点新闻 | 常写成 `姓名(单位)`，如「郭晨帆(中石油)、张宇迪(英国巴斯大学读博)」 |
| **3** | **「部分校友」/「毕业生名单」页** | 官网「研究团队 → 部分校友」 | 按届列姓名+专业，但**通常滞后一届**，应届生查不到 |
| **4** | **学生个人页面** | 官网 `.../sbss/<hash>.htm` | 多为空壳，只有姓名。不值得投入时间 |

**必做动作：把整份 PDF 提取成文本再全文检索。** 年报动辄几十页，靠肉眼翻必然漏。本机常无 `pdftotext`，用 `pdfminer.six` 兜底：

```bash
python -c "
from pdfminer.high_level import extract_text
t = extract_text('report.pdf'); open('t.txt','w').write(t)
"
grep -n "姓名" t.txt   # 或 python 里 find()
```

**配套动作：主动换搜索引擎。** 默认搜索工具的索引覆盖不全。**带引号的精确名检索交给 Bing**，常能多命中三类来源：机构个人页面、领英档案、专利库。抓法：`https://www.bing.com/search?q=%22姓名%22`（URL 编码中文）。

**副产品**：专利库（PatentGuru 等）的发明人条目带**申请人单位**，可反查此人的本科/早期就读学校。

**⚠️ 领英专属坑（务必记住）**：`cn.linkedin.com` / `linkedin.com` 在国内直连一律返回 **HTTP 451**（合规拦截，正文 0 字节）。所以：
- 你能做到的只是**从 Bing 索引里取到领英 URL**（`cn.linkedin.com/in/<中文名>-<数字ID>`），**取不到页面内容**——不要试图 curl 或 WebFetch 后说"领英上有 XX 信息"，那是没读到的。
- Bing 收录的领英标题常是「旅游度假 — 经理」这类**占位式行业标签**，这是 LinkedIn 对未完善/未登录可见档案的默认填充，**不能当作此人的真实职位**，也不能据此认定是目标人物。
- 结论口径：领英只能定性为「存在一个同名档案」的**线索**，**永远不作为结论级证据**。

## 输出格式（用户要的是结论，不是过程）

1. **结论先说**：学历/去向 = 查到 / 查不到。一句话讲完。
2. **身份确认表**：把命中的公开来源逐条列出（时间 + 内容 + 出处），让用户能自己复核
3. **为什么查不到**：说清是哪个信息载体缺位（学术路线 vs 机构岗位路线），不要含糊
4. **同名干扰**：单列，标明"均非本人"及各自单位，防止用户搜到隔壁那个人
5. **下一步**：给出 2–3 条**具体可执行**的路径，不要写"建议进一步核实"这种空话
6. **用途提醒**：涉及背调/入职核实时必须写

## 视觉呈现

用 `show_widget` 画证据链时间线或结论卡片：命中项用中性色罗列，最后的"学历状态 + 下一步"用单独一块强调色卡片。深色主题下用 800 级填充 + 200 级描边。

## 易踩的坑

- ❌ 搜"姓名 + 学历" → 直接命中同名的学者，越搜越偏
- ❌ 拿"同为该校校友"当证据 → 只能证明同级同专业，不能证明是同一人
- ❌ 把竞赛/活动新闻稿里的并列署名当"关系证明" → 只能证明当年同队，不能推出现在的关系
- ❌ 数据库无结果 → 断言"这人没有学历记录"（要说"公开渠道零记录"）
- ❌ 抓完 PDF 就说"文末没有 XX" → 长 PDF 尾部常被截断，会得出错误的"不存在"。**先换路径复核**
- ❌ 用"姓名 + 学科大类相符"当同一人证据 → "都是计算机"这种筛子太粗，只能说不冲突，不能叫"最匹配"。**要用出生年/籍贯/入学年份这类可比硬字段，且必须找到一条把两个单位连起来的记录**
- ❌ 用"籍贯/身份证前六位吻合"直接推出母校 → 地域吻合只证明地域吻合。身份证前六位是**户籍县区**代码，不指向任何学校；要定到院校，必须有**含「毕业院校」字段的名单**（拟聘公示、任职公示、学位论文、毕业生名录）
- ❌ 把"A 单位的某某"与"B 单位的某某"默认成同一人 → 跨单位关联必须有一条**把两个单位连起来的记录**（同一成果署名、同一方向、同一论文、人事流动公告）
- ❌ 只查一轮就收工 → 至少 8–12 次定向检索才算尽力，且要在回复里体现检索路径
- ❌ **只用一个搜索引擎就下「查不到」的结论** → 默认搜索工具索引不全（本次搜同一名字，默认搜索返回的是无关网页，换 Bing 后立刻命中机构个人页、领英、专利库）。**精确名检索（加引号）必须用第二个引擎复核**
- ❌ **查「就业去向」只搜新闻稿** → 正解是优先找机构的**年度报告 PDF** 和**毕业生名单 / 部分校友页**，那里是 `姓名 / 去向单位` 逐个列出的。拿到 PDF 后**必须提取全文再检索**（pdfminer），不要靠翻页
