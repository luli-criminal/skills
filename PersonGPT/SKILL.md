# 人物公开履历溯源

## 铁律（先读这一节，它比方法更重要）

1. **绝不做"制度性倒推"当结论。** 典型错误：看到"教授级高级工程师"就说"正高职称通常要求硕士及以上"。这类推断看着专业，实际是幻觉——现行《工程技术人才职称评价基本标准条件》（人社部发〔2019〕16 号）明确正高只需**大学本科及以上**，且专设破格条款。**凡引用政策门槛，先取原文再下结论。**
2. **"查不到"≠"不存在"。** 要明确告诉用户是"公开渠道零记录"，不是"这人没学历/没毕业"。
3. **区分"实际观感"与"条文/事实"。** "这个岗位的人普遍学历高"是竞争结果，"规定要求硕士"是条文，两码事。
4. **发现自己的结论错了，立刻当面纠正并写进记忆**，不要悄悄改口。
5. **同名干扰必须单独列一节。** 中文姓名撞车极其严重（一个普通的三字姓名，实测能撞到 5–7 个完全不相干的人：高校学者、企业工程师、地方记者、政府干部各一），不列就是给用户埋雷。
6. **用途提醒写进结尾**：如果用户在背调/入职核实，公开检索只能定性、不能定论，正式结论要走对方提供的学历证明或官方渠道。
7. **绝不假设目标人所在单位的类型。** 公示制度只存在于**有公示义务的单位**（机关事业单位、国企、公立机构）。民企、外企、互联网公司**没有公示义务**——在"翻公示名单"上死磕是纯粹的浪费。**先做第 0 步归类，再选入口。**

## 第 0 步：先判断「单位类型」（本 skill 最容易犯的偏差）

⚠️ 本 skill 的早期案例几乎全是**央媒与科研院所**，容易让人误以为"翻公示名单"是通例。**它不是。** 不同单位的公开制度完全不同：

| 单位类型 | 公示 / 年报义务 | 首选入口 |
|---|---|---|
| 机关 / 事业单位 / 公立医院 / 公立学校 | ✅ 强 | 技巧二 + 技巧四 |
| 央媒 / 部委下属单位 | ✅ 强 | 技巧四 |
| 国企 / 央企 / 银行 / 电网 / 烟草 | ✅ 招聘拟录用公示（多挂官网招聘栏或上级集团站） | 技巧四；技巧三（企业年报的员工/人才章节） |
| 高校 / 科研院所 | ⚠️ 部分（招聘、职称评审） | 技巧三（年报、答辩新闻、校友页）+ 学位论文库 |
| 中小学教师 / 公务员 | ✅ 强 | 技巧二 |
| 民企 / 互联网大厂 | ❌ 无 | 校招榜单、**开源社区（GitHub/Gitee）**、专利库、领英/脉脉/BOSS 线索、产品与项目署名 |
| 外企 / 海外机构 | ❌ 无 | LinkedIn、学校校友页、会议 speaker bio、ORCID、Google Scholar |
| 自由职业 / 创业 / 个体 | ❌ 几乎无 | 工商备案信息、作品署名、行业协会名录 |

**判断方法**：从已锚定的公开痕迹里看**单位性质与岗位性质**，不要凭印象。

**同一个制度，在不同系统里叫法不同**——搜的时候要把这些词都试一遍，漏一个词就可能漏掉整份名单：

> 拟聘用人员公示 / 接收毕业生情况公示 / 拟录用人员公示 / 公开招聘结果公示 / 招聘拟录取名单 / 干部任职公示 / 职称评审通过人员公示

## 第一步：锁定唯一身份（最重要的一步）

搜 `"姓名" + 机构名`。不要搜"姓名 学历"！搜学历会直接落到同名的学者身上（因为**学者的学历是公开的，机构技术岗/行政岗的学历不是**）。

拿到一条能锚定单位的公开记录后（新闻稿、标准起草人名单、论文署名、奖项名单、活动通稿），记下**单位全称 + 内部部门名**，后面所有检索都带上这个锚。

## 第二步：按"信息载体"选路径（决定成败）

人物的公开度取决于 TA 走的是哪条路线：

| 路线 | 典型公开痕迹 | 学历/去向是否可得 |
|---|---|---|
| **学术路线**（研究生、高校教师） | 个人主页（`*.github.io` 很常见）、论文 affiliation、推免/录取名单 PDF、学位论文 | ✅ 通常可得，且个人主页信息最全 |
| **机构 / 企业技术岗**（部委、央媒、研究院、国企与大厂工程师） | 团体标准起草人名单、行业奖项名单、专业期刊论文、内部讲座通稿、**开源仓库与产品署名** | ⚠️ 体制内一律只署**职务**；民企则**连职务都少**，但开源痕迹可反查 |
| **行政/管理岗** | 政府任职公示、单位官网领导介绍 | 任职公示常附**学历+毕业院校**，是高价值来源 |
| **学生 / 应届毕业生** | 竞赛获奖名单、**本科院校推免名单公示**、学院新闻稿；**导师主页「课题组成员」页（字段最全）**、机构年报「毕业生概况」、实验室答辩新闻、「部分校友」页、校级优秀毕业生名单 | ✅ 在校身份好查；**就业去向也可查 —— 优先走「导师主页课题组成员页」，其次机构年报/毕业生名单，见技巧五、技巧三** |

## 第三步：定向检索清单（照单打，别乱搜）

按顺序试，每步记录"命中/未命中"：

1. `"姓名" + 机构名` —— 锚定身份
2. `"姓名" + 机构名 + 硕士/博士/毕业于/学位` —— 最优先
3. **行业标准/国标起草人名单** —— 团体标准、国家标准、行业规范的起草人列表，能确认部门与工作内容
4. **奖项名单** —— 行业内奖项（如新闻行业的"王选新闻科学技术奖"）获奖名单常带**完成单位 + 完整姓名列表**
5. **知网/万方作者页、会议论文集** —— 能拿到作者单位，但**拿不到作者简介**（见下节）
6. **全国专业标准化技术委员会（TC）委员名单** —— `std.samr.gov.cn` 上有「委员姓名 / 委员会职务 / 专业特长 / 加入时间」；注意该页可能已下架
7. **单位人才计划 / 先进表彰名单** —— 偶尔附个人小传
8. **同名干扰排查**：`"姓名" + 学位论文` / `"姓名" + 教授/副教授` —— 主动把撞车的人找出来并排除
9. **机构/院系的「年度报告」与「毕业生名单/部分校友」页** —— 查**就业去向**时的第一顺位，见技巧三；**在校生/应届生另有更强的入口：导师个人主页的「课题组成员」页，见技巧五**
9b. **本科院校的「推免（推荐免试）名单公示」** —— 拿本科**专业 + 学号（→入学年份）**，见技巧六
9c. **校级「优秀毕业研究生 / 优秀毕业生」名单** —— 确认**届别 + 培养层次（硕/博）**，但不含去向
10. **换引擎复核**：`bing.com/search?q="姓名"` —— 默认搜索无结果时的必要动作，不是可选动作
11. **领英（LinkedIn）**、**专利库** —— 补充来源；专利的申请人单位可反查本科学校
12. **用人单位的「接收毕业生 / 拟录用 / 公开招聘结果」公示** —— 见技巧四。**不限于央媒部委**：国企、公立医院、公立学校、地方事业单位都有同类名单
13. **开源社区（GitHub / Gitee）与个人博客** —— **民企技术岗最有效的入口**（比公示名单有用得多）：profile、README、commit 邮箱域名、项目署名都能反推雇主与在职时间
14. **会议 speaker bio / 播客 shownotes / 访谈稿** —— 常附一段定型个人履历（"XX，毕业于 XX 大学，现任 XX"）

## ★ 高价值技巧：期刊「作者简介」是纸质版专属

**这是本 skill 最值钱的一条。**

很多行业期刊强制要求文末附作者简介，且**格式固定包含学历与职称**。例如《中国传媒科技》投稿规则：

> 作者简介：姓名(出生年份—)，性别，籍贯，**学历/职称/职务**，研究方向

也就是说：**纸质版/原版 PDF 上印着这个人的出生年、学历、职称。**

但是——**知网、万方、维普、国家哲学社会科学文献中心（ncpssd）全部只收录摘要和作者单位，不收录作者简介。** 网上流传的 ChinaXiv / archive.org 版本多半是**预印本**，简介被裁掉。

**所以：**
- 不要因为数据库里没有就判定"查不到"，要说明"信息存在但只在纸质版上"
- 给用户的下一步是：**纸本期刊、图书馆原文传递、或购买当期**
- 定位方法：先在 ncpssd（`ncpssd.org`）按刊名+年+期翻目录，拿到**页码**；再去 `d.wanfangdata.com.cn/periodical/<刊号><年份><期><序号>` 试详情页（常需安全验证）
- 其他期刊同理，先查该刊的**投稿指南**确认是否强制作者简介

## ★ 高价值技巧二：各类用人单位的「招聘 / 公示」名单

**注意：这套制度不限于机关事业单位。** 事业单位、国企、公立医院、公立学校都按同一套人社口径发公开招聘名单。**但民企/外企/互联网不在其中**（见第 0 步）。

公开招聘会分多轮公开名单，**不同轮次的字段完全不同**，选错了就等于白看：

| 名单类别 | 典型字段 | 是否含学历/院校 |
|---|---|---|
| **拟聘用人员公示** | 招聘单位及岗位 / 姓名 / **学历学位及专业** / **毕业院校（原工作单位）** | ✅ **含，一步到位** |
| 报名、资格审查、笔试、面试、体检名单 | 序号 / 姓名 / 身份证号 / 准考证号 / 成绩 | ❌ 只含身份证号，不含院校 |
| 干部任职公示 | 姓名 / 性别 / 民族 / 出生年月 / **学历 / 毕业院校** / 简历 | ✅ 含（行政岗首选） |
| 拟录用人员公示（国企口径） | 姓名 / 性别 / **学历 / 毕业院校 / 专业** / 拟聘岗位 | ✅ 含 |
| 职称评审通过人员公示 | 姓名 / 单位 / **学历 / 现职称** / 申报职称 | ⚠️ 常只列职称，学历看单位 |

- 拟聘公示样式由人社部事业司统一规定，见「中央和国家机关事业单位公开招聘服务平台 → 相关下载 → 拟聘人员公示（样式）」。**只要拿到这一类公示，学历+院校+原工作单位三样同时到手。**
- **身份证号前六位 = 户籍所在县区的行政区划代码**，可到民政部 `xzqh.mca.gov.cn` 或民政部《县以上行政区划代码》页查县名。**这是比"籍贯自报"更硬的佐证**（例：代码前四位指向地级市，第五、六位指向其下辖的具体县/区）。
  - 但要注意三条边界：①它是**户籍登记地**，不等于出生地、更不等于籍贯；②它**不指向任何学校**；③"与某人同籍贯"只能证明籍贯吻合，**不能替代毕业院校字段**。
- **老公示的坑**：约 10 年前的公示页面在单位 / 部委网站改版或迁移后路径常失效，站内检索也搜不到，只能用搜索引擎的全文索引碰，或**直接向用户索取原始链接**。

## ★★★ 高价值技巧三：机构年报与毕业生名单（查「就业去向」的第一入口）

**查"就业去向"时，最优来源不是新闻稿，而是机构自己出的年度报告和毕业生名单——它们会逐个列出「姓名 + 去向单位」。**

按价值排序，四个入口：

| 优先级 | 入口 | 形态 | 说明 |
|---|---|---|---|
| **1** | **机构「年度报告」（Annual Report）** | 官网「年报 / 最新成果」下的 PDF；企业年报的员工构成章节 | 「人才培养 → 毕业生概况」章节逐个列 `姓名 / 去向单位`，含读博、选调、企业。**一份年报即可定案**。高校院系、实验室、企业、公益机构都可能出 |
| **2** | **课题组「毕业生答辩」新闻** | 实验室站点新闻 | 常写成 `姓名(去向单位)`，如「某某(某央企)、某某(赴英读博)」 |
| **3** | **「部分校友」/「毕业生名单」页** | 官网「研究团队 → 部分校友」 | 按届列姓名+专业，但**通常滞后一届**，应届生查不到 |
| **4** | **学生个人页面** | 官网 `.../sbss/<hash>.htm` | 多为空壳，只有姓名。不值得投入时间 |

**必做动作：把整份 PDF 提取成文本再全文检索。** 年报动辄几十页，靠肉眼翻必然漏。本机常无 `pdftotext`，用 `pdfminer.six` 兜底：

```bash
python -c "
from pdfminer.high_level import extract_text
t = extract_text('report.pdf'); open('t.txt','w').write(t)
"
grep -n "姓名" t.txt   # 或 python 里 find()
```

**配套动作：主动换搜索引擎。** 默认搜索工具的索引覆盖不全。**带引号的精确名检索交给 Bing**，常能多命中三类来源：机构个人页面、领英档案、专利库。抓法：`https://www.bing.com/search?q=%22姓名%22`（URL 编码中文）。

**副产品**：专利库（PatentGuru 等）的发明人条目带**申请人单位**，可反查此人的本科/早期就读学校。

**⚠️ 领英专属坑（务必记住）**：`cn.linkedin.com` / `linkedin.com` 在国内直连一律返回 **HTTP 451**（合规拦截，正文 0 字节）。所以：
- 你能做到的只是**从 Bing 索引里取到领英 URL**（`cn.linkedin.com/in/<中文名>-<数字ID>`），**取不到页面内容**——不要试图 curl 或 WebFetch 后说"领英上有 XX 信息"，那是没读到的。
- Bing 收录的领英标题常是「旅游度假 — 经理」这类**占位式行业标签**，这是 LinkedIn 对未完善/未登录可见档案的默认填充，**不能当作此人的真实职位**，也不能据此认定是目标人物。
- 结论口径：领英只能定性为「存在一个同名档案」的**线索**，**永远不作为结论级证据**。

## ★★★ 高价值技巧四：用人单位的「接收毕业生 / 拟录用人员公示」

**适用于所有有公示义务的单位（见第 0 步），不限于央媒部委。**

依据人力资源社会保障部要求，有公示义务的单位每年公示当年**接收应届高校毕业生**或**公开招聘拟录用人员**情况，而这类名单会逐个列出：

```
序号 | 单位 | 岗位 | 姓名 | 毕业院校 | 专业 | 学历
```

**学历 + 毕业院校 + 专业 + 岗位四项一次到手**，是本 skill 目前见到字段最全的公开名单。

**挂载位置随单位类型变化**：单位官网「招聘 / 人才」栏、上级集团或主管部门网站、地方人社局「事业单位招聘」栏。**别只在小范围里找。**

### 附件形态有四种，先判形态再选解析方式

| 形态 | 处理方式 |
|---|---|
| 网页表格（文字） | 正则抽 `tr/td` 即可 |
| 图片（PNG/JPG） | **必须 OCR** |
| XLS / XLSX | `xlrd` / `openpyxl` 直接解析 |
| 扫描 PDF（无文字层） | 先渲染成图，再 OCR |

⚠️ **不要靠猜 URL 找其他年份的附件。** 实测某央媒三年的附件分别是：多张 PNG 图片、一个 `download/*.xls`、一个 `gongshi<年>/gsmd.pdf`——**三种完全不同的形态与路径规律，年份拼不出来**（换年份的同类路径一律 404）。正确做法是**先用搜索引擎找到当年那篇公示页，再从页面里取附件链接**。

⚠️ **注意「公示」不年年发**：实测某央媒某一年度只有招聘公告、没有接收公示。查不到时要说「该年度未公示」，而不是「此人不存在」。

⚠️ **名单的覆盖范围有限**：只覆盖**应届统招**入职者。社会招聘、内部调动、聘用制、实习转正的人**都不在名单里**，推不出任何其他结论。

### ★ 扫描件 OCR：用 macOS 自带 Vision（本机验证可行）

公示附件**经常是没有文字层的扫描图**（`pdfminer` 提出来只有 1 个字符），此时必须 OCR。

**本机（macOS 15）可行方案 = pyobjc 调 Vision 框架**：

```bash
pip install pyobjc-framework-Vision pyobjc-framework-Quartz
```

```python
import Vision, Quartz
from Foundation import NSURL
from PIL import Image

def ocr(path, band=1400, overlap=120):
    """分块 OCR：巨图必须切带，否则 Vision 会内部降采样丢细节"""
    src = Image.open(path).convert('RGB'); W, H = src.size
    res, y = [], 0
    while y < H:
        y2 = min(H, y + band)
        src.crop((0, y, W, y2)).save('/tmp/_b.png')
        u = NSURL.fileURLWithPath_('/tmp/_b.png')
        s = Quartz.CGImageSourceCreateWithURL(u, None)
        cg = Quartz.CGImageSourceCreateImageAtIndex(s, 0, None)
        r = Vision.VNRecognizeTextRequest.alloc().init()
        r.setRecognitionLevel_(0)                        # ★ 0=accurate，1=fast！中文必须用 0
        r.setRecognitionLanguages_(["zh-Hans", "en-US"])
        r.setUsesLanguageCorrection_(False)              # ★ 名单类关掉纠错，避免自动改字
        Vision.VNImageRequestHandler.alloc().initWithCGImage_options_(cg, None)\
              .performRequests_error_([r], None)
        for o in r.results():
            c = o.topCandidates_(1)
            if c and len(c):
                bb = o.boundingBox()
                res.append((y + (1.0 - bb.origin.y) * (y2 - y), bb.origin.x, str(c[0].string())))
        if y2 >= H: break
        y = y2 - overlap
    return sorted(res, key=lambda t: (round(t[0], 1), t[1]))
```

**四条硬约束（都是踩过的坑）**：

1. **`setRecognitionLevel_(0)` 才是 accurate**；写 `1` 是 fast 模式，中文会整片识别成乱码（输出全是 `4K#*` 这种拉丁字符）。这是最容易搞错的一处。
2. **巨图必须分块**：3000×13165 这种长图直接送进去会被降采样，细节全丢。切 1400px 高的带、留 120px 重叠。
3. **名单类文本关掉 `usesLanguageCorrection`**，否则它会"顺手"把罕见姓名改成常见字。
4. **不要走 `swiftc`**：本机 CommandLineTools 的 SDK 与编译器版本不匹配（`redefinition of module 'SwiftBridging'` / `this SDK is not supported by the compiler`），编译必失败，且没装 Xcode 无法修。**直接用 pyobjc**，它是预编译 wheel，运行时调系统框架，不需要编译器。

**OCR 结果必须自检**：拿名单里已知一定存在的字（如姓氏、表头「姓名」「毕业院校」）验证识别正常，再看目标名字不在其中，才能下"不在名单里"的结论。**不能拿 OCR 的"没搜到"直接当结论。**

## ★★★ 高价值技巧五：导师个人主页的「课题组成员」页（查在校生 / 应届生去向的最佳单一来源）

**高校教师个人主页系统**（形态如 `jszy.<校域名>/<导师拼音>/zh_CN/index.htm`，中文栏目常挂在 `tdcy`（团队成员）路径下）通常带一个「Research Group / 团队成员 / 课题组成员」栏目，**逐个学生**列出完整档案：

```
毕业年级：2025届硕士 ｜ 毕业去向：XXX 有限公司 ｜ 学历介绍：本科 XX 大学 XX 学院；硕士 XX 大学 XX 重点实验室 ｜ 专业 ｜ 研究方向 ｜ 邮箱
```

**毕业去向 + 本科院校 + 硕士院校 + 专业 四项一次到手，且是一手来源（导师自己维护）。**

用法与坑：
- 先搜 `"导师姓名" + 学校` 找到其主页，再进「团队 / Research Group / 课题组成员」栏目
- **同一院系不同导师的页面字段完整度差别极大**；在 A 导师页面找不到目标学生时，**换同院系其他导师的页面再试**（学生常挂在多个导师/课题组页面下）
- 该栏目往往**分「在读」与「毕业生」两段**，毕业生段按届排列，是查去向的主力

## ★★ 高价值技巧六：本科院校的「推免名单公示」

本科院校每年公示**推荐免试研究生名单**，典型字段：

```
学号 | 姓名 | 专业 | 参与推免学业排名 | 奖励加分 | 最终排名
```

- 是确认**本科专业 + 入学年份（学号里常含年份）** 的硬来源，比竞赛新闻稿精确
- ⚠️ 「推免」只说明**拿到资格**，**不等于最终去向**——要去向得看研究生院校的名单或导师页
- 同一条名单里常能看到同专业同级的其他人，方便交叉验证（本次同页就同时命中队里另两名成员）

## ★ 高价值技巧七：高校机构知识库的学位论文条目

不少高校有公开的机构知识库（形态如 `openir.<校域名>`），学位论文条目含：**作者、学位层次、专业、答辩日期、导师及其单位**。

- 能拿到**导师**与**答辩日期（→届别）**，但**通常没有就业信息**
- ⚠️ 这类站点多为 **SPA**：首页只有几 KB 的 JS 壳，**curl 拿不到内容**，手拼的搜索 URL 一律返回空壳。要用浏览器环境，或改用搜索引擎去命中它的条目页

## 输出格式（用户要的是结论，不是过程）

1. **结论先说**：学历/去向 = 查到 / 查不到。一句话讲完。
2. **身份确认表**：把命中的公开来源逐条列出（时间 + 内容 + 出处），让用户能自己复核
3. **为什么查不到**：说清是哪个信息载体缺位——**先讲单位类型**（该类单位有没有公示义务），再讲路线（学术路线 vs 机构/企业岗位路线），不要含糊
4. **同名干扰**：单列，标明"均非本人"及各自单位，防止用户搜到隔壁那个人
5. **下一步**：给出 2–3 条**具体可执行**的路径，不要写"建议进一步核实"这种空话
6. **用途提醒**：涉及背调/入职核实时必须写

## 视觉呈现

用 `show_widget` 画证据链时间线或结论卡片：命中项用中性色罗列，最后的"学历状态 + 下一步"用单独一块强调色卡片。深色主题下用 800 级填充 + 200 级描边。

## 易踩的坑

- ❌ **假设目标人一定在央媒 / 部委 / 体制内** → 公示制度只对有公示义务的单位成立。民企、外企、互联网**没有公示义务**，"翻公示名单"对他们是死路。**先做第 0 步归类**
- ❌ **只用一种叫法搜公示** → 同一套制度在不同系统的名字不同（拟聘用 / 接收毕业生 / 拟录用 / 公开招聘结果 / 任职 / 职称评审），漏一个词就可能漏掉整份名单
- ❌ 搜"姓名 + 学历" → 直接命中同名的学者，越搜越偏
- ❌ 拿"同为该校校友"当证据 → 只能证明同级同专业，不能证明是同一人
- ❌ 把竞赛/活动新闻稿里的并列署名当"关系证明" → 只能证明当年同队，不能推出现在的关系
- ❌ 数据库无结果 → 断言"这人没有学历记录"（要说"公开渠道零记录"）
- ❌ 抓完 PDF 就说"文末没有 XX" → 长 PDF 尾部常被截断，会得出错误的"不存在"。**先换路径复核**
- ❌ 用"姓名 + 学科大类相符"当同一人证据 → "都是计算机"这种筛子太粗，只能说不冲突，不能叫"最匹配"。**要用出生年/籍贯/入学年份这类可比硬字段，且必须找到一条把两个单位连起来的记录**
- ❌ 用"籍贯/身份证前六位吻合"直接推出母校 → 地域吻合只证明地域吻合。身份证前六位是**户籍县区**代码，不指向任何学校；要定到院校，必须有**含「毕业院校」字段的名单**（拟聘公示、任职公示、学位论文、毕业生名录）
- ❌ 把"A 单位的某某"与"B 单位的某某"默认成同一人 → 跨单位关联必须有一条**把两个单位连起来的记录**（同一成果署名、同一方向、同一论文、人事流动公告）
- ❌ 只查一轮就收工 → 至少 8–12 次定向检索才算尽力，且要在回复里体现检索路径
- ❌ **只用一个搜索引擎就下「查不到」的结论** → 默认搜索工具索引不全（本次搜同一名字，默认搜索返回的是无关网页，换 Bing 后立刻命中机构个人页、领英、专利库）。**精确名检索（加引号）必须用第二个引擎复核**
- ❌ **查「就业去向」只搜新闻稿** → 正解是优先找机构的**年度报告 PDF** 和**毕业生名单 / 部分校友页**，那里是 `姓名 / 去向单位` 逐个列出的。拿到 PDF 后**必须提取全文再检索**（pdfminer），不要靠翻页
- ❌ **pdfminer 提取出 1 个字符就以为文件坏了** → 那是**无文字层的扫描件**，必须走 OCR（见技巧四的 Vision 方案）
- ❌ **靠猜 URL 找历年公示附件** → 附件路径不规律（图片、`download/*.xls`、`gongshi<年>/gsmd.pdf` 混用），且很多年份根本没发。**先搜到当年那篇公示页，再从页面里取链接**
- ❌ **把"某年公示里没有此人"当成"此人不在该单位"** → 公示只覆盖**应届统招**入职者。社会招聘、内部调动、聘用制、实习转正的人**都不在名单里**。查不到只能说明"不是那一年的应届生"，不能说别的
- ❌ **OCR 用的是 fast 模式（`recognitionLevel=1`）** → 中文会成片变乱码。必须用 `0`（accurate），且长图要分块
- ❌ **用 3 年制学硕的惯性推算届别** → 两年制专硕（如某重点实验室的电子信息专硕）「2023 级」= 「2025 届」，与三年制整整差两年。**先确认学制，再谈届别**；拿不准就用校级「优秀毕业研究生」名单反查届别
- ❌ **在 Bing 上做「常见大姓」中文人名的精确检索** → 会被姓氏词典整片淹没（搜某常见姓氏人名，回来的是该姓氏的百科词条，有效结果 0 条）。换引擎是「补索引不全」的手段、**不是万能药**；遇到大姓要果断换回默认搜索或其他库
- ❌ **把机构知识库当成可 curl 的检索站** → openir 类站点首页只有 JS 壳（约 5 KB），手拼搜索 URL 一律返回空壳。要拿数据得用浏览器，或让搜索引擎代劳命中条目页
